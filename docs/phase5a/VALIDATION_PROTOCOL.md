# Phase 5A temporal feasibility: later validation protocol

This is an unvalidated diagnostic source, not a strategy or trading indicator.
No chart, Pine compiler or TradingView account was accessed in Phase 5A.

## Frozen scope and source design

DATA_START = 2026-11-01T00:00:00Z; TRADE_START = 2026-11-04T00:00:00Z;
TRADE_END = 2026-12-01T00:00:00Z. Inputs have bar opens in [DATA_START,
TRADE_END); signal-close eligibility is [TRADE_START, TRADE_END). A final bar
closing at TRADE_END can update numerical state, but cannot create eligibility.
No signal is actually generated by this probe. Warm-up has no diagnostic output.
The first permitted diagnostic uses the 23:45–00:00 bar closing on November 4.

EMA20 and EMA50 seed from the first authorized Close. ATR14 seeds from the mean
of fourteen authorized TR values; before that it is na. Initial TR is H-L,
without close[1]. Later TR uses an explicitly stored authorized previous close.
Each timeframe must encounter its exact anchor bar, followed by contiguous
valid positive OHLC. A missing anchor, gap or invalid candle permanently
quarantines that context for this run. No skipping, zero filling or native
indicator fallback occurs. There is no reset at TRADE_START. Native EMA/RMA,
DMI/RSI, pivots, signal predicates, K controls and trading execution are absent.
This is a representative state/HTF feasibility probe, not full indicator parity.

Hourly EMA50 seeds independently inside the requested context. The tuple
returned by f_hour_confirmed offsets every item in that context: last EMA50 [1],
EMA50 three bars before it [4], close [1], hourly end [1], observation count [1].
request.security uses lookahead_on with this already-offset expression tuple.
This implements the documented offset-expression pattern; it does not offset
already merged chart values. No unshifted hourly numerical value is returned.
The prior hour becomes available on the subsequent execution interval: the
10:00–11:00 hour is first consumed at the close of the 11:00–11:15 chart bar.
A timestamp-freshness check rejects stale gaps_off values, and requires sixty
confirmed hours. Chart diagnostic readiness also requires 200 closed chart bars.
These are existing minimum-history contracts, not new trading filters.

var state, without varip, is intended to follow normal rollback/commit semantics.
The chart state updates only on barstate.isconfirmed. The hourly expression
relies on offset confirmation rather than barstate.isconfirmed in security.
Actual persistence, rollback and merged timing must still be tested in Pine.
Outputs are Data Window diagnostics only, masked outside eligibility, with
one-bar plot offset intended to locate them at the owning close timestamp.
There are no lines, labels, background colors, alerts or orders. Plot-offset
Data Window alignment is an explicit runtime check, not an established fact.

## Separately authorized real validation steps

1. Obtain explicit authorization and establish a dedicated standard 15m
   non-Holdout environment whose dataset access and visible chart cannot expose
   January–October 2026 data. It must include the exact November 1 anchor in both
   15m and 60m contexts. Do not open an ordinary chart that may load/show Holdout
   as a substitute. Pine date gates do not control the platform's chart history
   or guarantee request.security fetch boundaries. If a permitted environment
   cannot be demonstrated, STOP with the access/isolation gate UNVERIFIED.
2. In that permitted environment only, paste the exact hashed Pine artifact into
   Pine Editor, compile, and preserve genuine compiler output, source hash,
   platform date/version and any diagnostics. No source fix may be silently
   substituted. A revised artifact requires new versioned evidence and offline
   checks. Do not infer compilation from the Python tests or source inspection.
3. Record symbol/feed identity (Bybit linear BTCUSDT, distinct from inverse),
   standard chart type, 15m interval, requested 60m context, UTC timestamps,
   actual available data end, and dataset boundaries. Never assume all November
   or future December bars exist. No broker connection or trading alerts.
4. Compare authorized observations with a separately authorized reference fed
   exactly the same permitted 15m and 60m OHLC and anchor. In this current phase
   no such market input is acquired or compared. First observe initialization
   using a dedicated synthetic/non-Holdout fixture environment or separately
   authorized instrumentation; the delivered probe deliberately hides warm-up.
   Any warm-up instrumentation must stay in that dedicated environment and
   retain the same input gates, not expose warm-up on the normal probe.
5. Verify the initial 15m/60m EMA first-close seeds, first TR H-L, thirteen na ATR
   outputs then the fourteen-observation RMA seed. Compare nonconstant vectors
   and gaps. A run missing the anchor must remain unavailable, never reseed late.
6. At the 10:45–11:00 bar close, verify that the 10:00–11:00 hour is NOT consumed.
   At the 11:00–11:15 close, verify it IS consumed. Verify EMA [1]/[4] ownership
   entirely in HTF, plus hour-end and observation count. Compare historical,
   elapsed realtime, reload and an actually observed realtime hourly transition;
   replay alone does not establish all realtime behavior. Record exact tuples.
7. Verify no numerical reset at November 4, no diagnostic output before its
   first permitted close, and none at/after December 1. Verify Data Window
   offset placement at the owning timestamp; do not treat plot offset as an
   authorization mechanism or numerical timing adjustment.
8. For pre-anchor independence, use a dedicated synthetic fixture with different
   synthetic pre-anchor prefixes and identical authorized suffixes. Never inspect
   real Holdout to construct that comparison. Reload the permitted dataset with
   different amounts of authorized history and require identical anchor-based
   state; removing the anchor must quarantine rather than silently change seed.
9. Use the frozen numerical tolerance only for indicator values:
   abs(a-b) <= 1e-8 + 1e-10*max(abs(a),abs(b)). Timestamps, readiness booleans and
   observation counts must match exactly. Do not round to conceal divergence.
   Record the first difference, input hashes, source/config hashes and genuine
   evidence. No returns, orders, profitability or historical trade paths.
10. Submit independent review. Compiler success, runtime temporal isolation,
    numerical agreement and full Pine–Python execution parity are separate
    gates. This no-order probe cannot establish strategy execution, full logic
    parity or performance validity. Missing any necessary evidence leaves its
    gate UNVERIFIED. Do not start Phase 5B/5C automatically.

## Reproduce current offline checks

From the repository root:

    PYTHONDONTWRITEBYTECODE=1 sh tools/research_python.sh -m tests.run_phase5a_checks

This runs only the new synthetic tests with network/real-data denials and exact
frozen environment verification. Existing tests and evidence are untouched.
It is not a full historical regression rerun or a Pine execution harness.
